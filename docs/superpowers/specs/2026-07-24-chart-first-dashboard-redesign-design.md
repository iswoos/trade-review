# 차트 우선 진입 플로우 + 대시보드 리디자인

## 배경

지금은 앱을 열면 무조건 매매 기록 입력 화면(`TradeForm`)부터 보여주고, 매매를 실제로 저장해야만(`createTrade` 성공 후) 차트 화면(`StockDetail`)으로 전환된다(`App.tsx`의 `screen: 'form' | 'detail'` 상태, `handleSaved` 콜백). `StockDetail`도 `position`이 있을 때만 차트를 렌더링해서(`tab === 'chart' && position &&`), 매매 기록이 없는 종목은 차트만 미리 볼 방법이 없다.

이 설계는 두 가지를 함께 바꾼다:
1. **플로우**: 종목을 고르면(신규 검색이든 기존 포지션이든) 바로 차트로 가고, 매매 입력은 차트 화면 안에서 필요할 때 여는 바텀시트로 옮긴다.
2. **비주얼**: 지금 스타일 없는 시맨틱 HTML을, `design-taste-frontend` 스킬의 타이포/컬러/카드 규칙을 대시보드에 맞게 골라 적용한 카드형·라운드·단일 액센트 디자인으로 바꾸고, 다크모드를 지원한다.

두 작업은 화면을 처음부터 새로 짜는 김에 스타일도 같이 입히는 게 자연스러워 하나의 설계로 묶었다.

## 화면 구조

`App.tsx`의 화면 상태를 `'form' | 'detail'`에서 `'home' | 'chart'`로 바꾼다. 시작 화면은 `'home'`이고, 화면 전환은 매매 저장이 아니라 **종목 선택**에 걸린다.

### 홈 화면 (신규)

- **상단 검색창(통합형, 상시 노출)**: 타이핑하면 "내 포지션"(로컬 필터)과 "신규 검색 결과"(API 검색)를 그룹으로 나눠 한 목록에 보여준다. 어느 쪽을 선택해도 차트 화면으로 전환된다.
- **우측 상단 아이콘**: 기존 `BackupControls`(CSV 내보내기/가져오기)를 아이콘 버튼 뒤로 옮긴다.
- **보유 포지션 목록**: 정렬 기준을 유저가 선택할 수 있고(최근 매매순 / 티커·종목명 알파벳순 / 평가손익% 순), 기본값은 최근 매매순. 각 행(표준형)은 티커/종목명 + 평단 + 현재가 + 평가손익%.

### 차트 화면 (`StockDetail` 재구성)

- **상단 검색창**: 홈과 동일한 컴포넌트를 그대로 재사용해서 계속 떠 있는다. 다른 종목 검색·선택 시 홈으로 돌아가지 않고 바로 전환.
- **종목 타이틀 좌우 화살표**: 홈 화면의 "현재 정렬 기준" 순서를 따라 이전/다음 포지션으로 이동. **매매 기록이 없는(포지션 목록에 없는) 신규 검색 종목은 화살표를 비활성화한다.**
- **차트(`PriceChart`)**: 포지션 유무와 무관하게 항상 기본으로 렌더링(지금의 `position &&` 가드 제거). 포지션이 있으면 기존처럼 평단 점선·매수/매도 마커를 얹고, 없으면 시세 라인만 보여준다.
- **하단 액션 2종(바텀시트 트리거)**:
  - **"+ 매매 기록 추가"**(primary) — 기존 `TradeForm`에서 종목 검색 부분을 뗀 나머지(매수/매도, 체결가, 체결일, 수량, 태그, 확신도, 메모)를 바텀시트 내용으로 재사용.
  - **"매매 목록"**(secondary) — 기존 `StockDetail`의 '목록' 탭을 탭 전환 대신 바텀시트로 대체. 이 목록에서 항목을 선택하면 기존 `TradeBottomSheet`(상세 조회)가 그 위에 뜬다.

## 데이터 흐름

- **신규 DB 함수 필요**: 현재 `db/positions.ts`엔 `getPosition(db, ticker)` 하나만 있고 "전체 포지션 목록"을 가져오는 함수가 없다. 전체 매매 기록에서 티커를 distinct로 뽑아 각각 `getPosition`을 호출하는 형태의 신규 함수(예: `listPositions(db)`)가 필요하다.
- **홈 화면 검색**: 입력값 변경 시 (1) `listPositions` 결과를 클라이언트에서 티커/이름으로 필터링, (2) `searchSymbols`(기존 `src/api/quotes.ts`, FMP+yahoo-finance2 병렬 호출)를 동시에 실행하고, 두 결과를 "내 포지션"/"신규 검색 결과" 그룹으로 나눠 렌더링한다.
- **종목 선택**: 어느 그룹에서 선택하든 `App`의 화면 상태를 `'chart'`로, 대상 티커를 활성 티커로 설정한다.
- **차트 화면 진입**: `fetchHistory(ticker)`는 항상 호출. `listTradesByTicker`/`getPosition`은 호출하되 결과가 빈 배열/포지션 없음이어도 차트 렌더링을 막지 않는다.
- **좌우 네비게이션**: 홈 화면과 동일한 정렬 기준으로 정렬된 포지션 목록을 기준으로 현재 티커의 인덱스를 찾아 이전/다음으로 이동. 활성 티커가 이 목록에 없으면(신규 검색·매매 기록 없음) 양쪽 화살표 모두 비활성화.

## 비주얼 시스템

`design-taste-frontend` 스킬은 스스로 "13. OUT OF SCOPE"에서 대시보드/데이터 밀집 UI를 범위 밖으로 명시한다(Fluent/Carbon/Atlassian/Polaris를 대신 권장). 이 프로젝트는 그 권장 시스템을 쓰지 않고, 대신 스킬의 **타이포그래피(4.1)·컬러 캘리브레이션(4.2)·머티리얼리티/카드(4.4)·인터랙티브 상태(4.5)·데이터·폼 패턴(4.6)** 규칙만 대시보드에 맞게 가져온다. 히어로/마케팅 카피 관련 규칙(4.7 이후 대부분)은 대시보드에 해당 사항이 없어 적용하지 않는다.

- **색**: 오프화이트/화이트(`#FAFAF9`/`#FFFFFF`) 배경, 잉크 톤(`#18181B`) 텍스트, 단일 브랜드 액센트 Emerald(`#10B981`, 채도<80%, "AI 퍼플" 금지 규칙 준수). 손실(`#DC2626`)은 장식용 액센트가 아니라 손익 상태를 나타내는 기능색으로 취급(4.2의 "max 1 accent" 규칙은 장식적 브랜드 액센트에 대한 것이고, 기능적 상태색은 별도로 허용).
- **형태**: 카드형 로우, 모서리 반경 12–14px로 전체 통일(Shape Consistency Lock, 4.4). 그림자는 배경색에 tint된 옅은 그림자만 사용.
- **타이포**: `Inter` 계열 산세리프(한글은 `Pretendard` 병행), 숫자 데이터는 필요 시 굵게 강조. 대시보드 맥락이라 4.1의 "Inter 기본 지양" 규칙은 예외 적용(4.1 자체가 "public-sector/accessibility-first 사이트는 Inter 허용"이라 명시).
- **인터랙션**: 버튼 대비 WCAG AA 준수, 폼 입력 라벨 위/에러 텍스트 아래(4.6), 로딩·빈 상태·에러 상태 각각 구현.

## 다크모드

Tailwind v4의 `dark:` variant로 처리한다(8.A 토큰 전략 중 유틸리티 우선 방식). 프로젝트에 지금 CSS 인프라가 전혀 없어(Tailwind 미도입, 전역 CSS 없음), 이번 작업에서 Tailwind v4를 신규로 도입한다.

- 기본 모드는 `prefers-color-scheme`를 따른다(8.C).
- 순수 `#000000`/`#ffffff` 대신 오프블랙/오프화이트 사용(8.B).
- 페이지 전체가 단일 테마를 유지한다(4.11) — 화면 일부만 다크/라이트가 섞이지 않는다.
- 다크모드에서도 Emerald 액센트와 손실 레드의 인지 가능한 대비를 유지한다(브랜드 정체성 유지, 8.B).
- 개발 중 라이트/다크 양쪽 모두에서 확인한다(8.D).

## 기술 스택 변경
